## 1. 文档目的

本文档定义“镜舱（JingCang）”这一套完全本地化、可在单台 Windows 电脑上部署的浏览器云方案。系统面向人工兼容性测试和后续自动化测试，提供与 F2etest 类似的使用方式：测试人员从浏览器进入镜舱控制台，选择浏览器及版本，启动一个隔离测试舱，在网页中直接操作远程浏览器，并访问本机开发服务、局域网服务或线上服务。

## 2. 结论与推荐方案

推荐建设以下系统：

> Selenium Grid 4 Dynamic Grid + 官方 docker-selenium 镜像 + noVNC + 镜舱控制台 + 本地 SQLite 数据库 + Nginx 统一入口。

采用分阶段交付：

1. **技术验证版**：固定 Chrome、Edge、Firefox 节点，验证 noVNC、本机服务访问、线上服务访问和资源消耗。
2. **MVP**：交付浏览器卡片、会话创建、网页远程操作、会话终止、超时清理、基础登录和运行状态。
3. **V1 正式版**：切换到 Dynamic Grid，按需创建和销毁浏览器容器，支持版本矩阵、排队、录像、截图、审计和资源治理。
4. **扩展版**：接入 Playwright、Windows/IE 节点、macOS/Safari 节点、团队权限和 CI。

不推荐使用原版 F2etest 作为基础，因为其最后维护时间、CentOS 7、Node.js 10、Guacamole 0.9.3、旧 Windows Server 和认证机制均不适合新建长期系统。

## 3. 项目目标

### 3.1 核心目标

- 在本机通过 `http://localhost:8088` 或 `http://jingcang.localhost` 进入镜舱控制台。
- 以卡片或列表方式展示可用浏览器、版本、平台、状态和容量。
- 支持 Chrome、Microsoft Edge、Firefox，预留 Chromium 和 WebKit 入口。
- 用户选择浏览器、版本、分辨率、语言、时区和启动网址后创建会话。
- 浏览器会话使用独立容器运行，避免 Cookie、缓存、扩展和测试数据互相污染。
- 在控制台页面中通过 noVNC 操作浏览器地址栏、网页和开发者工具。
- 能访问 Windows 本机开发服务、同一 Docker 网络中的服务、局域网服务和线上服务。
- 会话结束或超时后自动释放浏览器容器、端口和临时数据。
- 支持记录会话信息、运行日志、截图和可选视频。
- 所有控制面、数据和测试产物默认只保存在本机。
- 可通过 Docker Compose 一键启动、停止、升级和备份。

### 3.2 次要目标

- 为自动化测试提供标准 Selenium WebDriver 地址。
- 预留 Playwright 测试入口和统一测试报告入口。
- 支持浏览器版本固定，保证回归环境可复现。
- 支持多个并发会话，并在资源不足时排队或拒绝。
- 支持局域网内其他设备访问控制台，但默认关闭该能力。

### 3.3 非目标

第一阶段不包含：

- 真实 Safari；真实 Safari 必须依赖 macOS 设备或第三方真机云。
- IE6～IE11；遗留 IE 后续通过隔离 Windows VM 节点单独接入。
- Android/iOS 真机管理。
- 公网 SaaS、多租户计费或外部客户接入。
- Kubernetes；单机版本优先使用 Docker Compose。
- 无限制保留全部历史浏览器版本。
- 替代专业渗透测试沙箱；浏览器容器仍应视为可访问网络的执行环境。

### 4.1 角色

| 角色 | 职责 |
|---|---|

### 4.2 核心用户故事

1. 作为前端开发，我希望打开控制台并选择 Chrome 某版本，以便访问本机 `localhost:3000` 项目进行兼容性检查。
2. 作为测试人员，我希望同时启动 Edge 和 Firefox，会话之间互不共享登录状态。
3. 作为测试人员，我希望选择 1366×768 或 1920×1080 分辨率，验证响应式布局。
4. 作为测试人员，我希望输入线上 URL 后直接启动浏览器，并在控制台中操作页面。
5. 作为管理员，我希望限制最大并发和单会话时长，防止浏览器耗尽内存。
6. 作为管理员，我希望看到活跃会话、排队请求、失败原因和资源使用情况。
7. 作为自动化开发，我希望将测试指向本机 Grid，并通过 `browserName`、`browserVersion` 选择环境。
8. 作为测试人员，我希望会话结束后下载截图或录像，但不长期保留浏览器个人数据。

| Hyper-V | 服务已运行 | 满足 |

建议生产化本机配置：

- Docker Desktop 内存保持 32 GB 或以上；
- 浏览器会话默认 2 CPU、2～3 GB 内存；
- 默认最大并发 4，压测后再调整；
- 单会话默认 60 分钟，最大 120 分钟；
- 浏览器容器使用 2 GB 共享内存；
- 录像默认关闭，按会话开启；
- 产物默认保留 7 天或总量不超过 50 GB。

```text

                │
                ▼

    ├── noVNC 路由解析与短期访问令牌
    ├── SQLite 元数据与审计
    └── 截图/录像/日志索引
                │
                ▼
Selenium Grid 4 Dynamic Grid
    ├── Router / Distributor / Session Queue

                ├── 192.168.x.x          → 局域网服务
                └── https://...          → 线上服务
```

## 7. 组件设计

| 组件 | 推荐技术 | 主要职责 |
|---|---|---|
| Web Console | React + TypeScript + Vite | 浏览器目录、会话创建、远程画面、会话列表、管理页 |
| Session API | Node.js LTS + TypeScript + Fastify | 鉴权、参数校验、会话编排、Grid 适配、产物索引 |
| Session Worker | 同一后端进程的 Worker 或独立 Worker | 超时回收、心跳、孤儿容器清理、录像归档 |
| Selenium Grid | 官方 Selenium Grid 4 | 浏览器能力匹配、会话排队与路由 |
| Browser Nodes | 官方 `selenium/standalone-*` 镜像 | 真实 Chrome/Edge/Firefox 浏览器和 noVNC |
| Viewer Gateway | 后端 WebSocket/HTTP 反向代理 | 把内部 noVNC 地址安全映射到 `/viewer/{sessionId}` |
| Metadata DB | SQLite | 用户、浏览器目录、会话、产物、审计、设置 |
| Reverse Proxy | Nginx | 单一入口、静态资源、API 和 WebSocket 转发 |
| Artifacts Store | 本地卷 | 视频、截图、下载文件、浏览器日志 |
| Docker Socket Proxy | 受限代理，可选但推荐 | 限制后端或 Dynamic Grid 可调用的 Docker API 范围 |

### 7.1 技术选型原则

- 单机优先，减少外部依赖。
- 所有运行组件容器化，宿主机只依赖 Docker Desktop。
- 不使用外部数据库、对象存储、消息队列或云鉴权。
- 浏览器版本和镜像标签必须固定，禁止正式环境使用 `latest`。
- 浏览器容器必须临时化，不保存用户 Profile。
- noVNC 端口不得直接暴露给公网或整个局域网。
- 原始 Docker Socket 不直接暴露给前端，也不通过 HTTP 公网暴露。

## 8. 部署模式

### 8.1 技术验证模式：固定节点

先启动三个独立节点：

| 节点 | Grid 端口 | noVNC 端口 | 用途 |
|---|---:|---:|---|
| Chrome | 4444 或注册到 Hub | 7900 | 验证 Chromium 系 |
| Edge | 4445 或注册到 Hub | 7901 | 验证 Microsoft Edge |
| Firefox | 4446 或注册到 Hub | 7902 | 验证 Gecko 系 |

该模式用于完成以下前置验证：

- noVNC 鼠标、键盘、中文输入和剪贴板是否正常；
- Chrome、Edge、Firefox 是否能打开本机开发服务；
- 浏览器开发者工具是否可用；
- 本机 HTTPS、自签名证书和代理如何处理；
- 每个浏览器容器实际 CPU、内存和启动耗时；
- Nginx 反向代理 WebSocket 是否稳定。

### 8.2 正式模式：Dynamic Grid

正式版只常驻控制面。收到会话请求后，Grid 根据能力映射动态启动浏览器容器；会话结束后删除容器。

浏览器能力示例：

```json
{
  "capabilities": {
    "alwaysMatch": {
      "browserName": "chrome",
      "browserVersion": "149",
      "platformName": "linux",
      "se:name": "manual-chrome-149",
      "se:recordVideo": false,
      "se:screenResolution": "1920x1080",
      "goog:chromeOptions": {
        "args": [
          "--start-maximized"
        ]
      }
    }
  }
}
```

Dynamic Grid 需要通过 TOML 配置把能力组合映射到固定镜像标签。正式部署时，镜像标签和浏览器目录使用同一份受版本控制的清单生成，避免控制台展示的版本与 Grid 实际能力不一致。

## 9. 关键技术验证：动态 noVNC 路由

Dynamic Grid 的临时浏览器容器位于 Docker 内部网络，其 noVNC 地址不能直接返回给用户浏览器。必须先验证并实现 Viewer Gateway。

建议验证顺序：

1. 后端创建 WebDriver Session，获得 `sessionId`。
2. 调用 Grid GraphQL，根据 `sessionId` 查询 `nodeId`、`nodeUri`、capabilities 和状态。
3. 确认 Dynamic Grid 子容器是否提供稳定标签或可查询元数据，用于建立 `sessionId → container/noVNC endpoint` 映射。
4. 由后端或专用网关把 `/viewer/{sessionId}/` 反向代理到内部 `http://browser-container:7900/`。
5. 同时代理 noVNC 的 WebSocket，并重写 base path。
6. 为 viewer 生成短期签名令牌，令牌只绑定一个 session、一个用户和一个过期时间。
7. 会话关闭时立即撤销路由和令牌。

若官方 Dynamic Grid 在目标版本中无法稳定提供该映射，则采用降级方案：

- 后端直接通过受限 Docker API 创建官方 standalone 浏览器容器；
- 容器仍运行 Selenium 和 noVNC；
- 后端自行记录容器 ID、4444 地址和 7900 地址；
- 自动化入口可继续通过独立 Selenium Grid 提供，人工会话由 Orchestrator 管理。

该降级方案不改变用户体验，是正式研发开始前必须验证的架构退出路径。

## 10. 浏览器矩阵策略

### 10.1 MVP 矩阵

| 浏览器 | 通道/版本 | 平台 | 默认启用 |
|---|---|---|---:|
| Chrome | Stable，固定完整镜像标签 | Linux amd64 | 是 |
| Edge | Stable，固定完整镜像标签 | Linux amd64 | 是 |
| Firefox | Stable，固定完整镜像标签 | Linux amd64 | 是 |
| Chromium | Stable，按需 | Linux amd64 | 否 |

### 10.2 V1 矩阵

- Chrome：当前稳定版、前一个主版本、Beta。
- Edge：当前稳定版、前一个主版本。
- Firefox：当前稳定版、ESR、Beta。
- Chromium：当前稳定版，可选。

### 10.3 版本管理规则

- `browser-catalog.yaml` 是浏览器目录的唯一事实来源。
- 每条记录包含浏览器名称、显示名称、主版本、完整镜像标签、平台、状态、默认标记和预计资源。
- 正式环境只使用完整日期标签或镜像 digest。
- 新版本先在预发布目录中验证，再切换为可用。
- 旧版本至少保留到项目兼容矩阵不再需要为止。
- 每月检查一次镜像更新，出现浏览器高危漏洞时提前升级。
- 不承诺所有历史版本可用；无法在当前基础镜像运行的版本进入“遗留 VM”范围。

示例：

```yaml
browsers:
  - id: chrome-stable
    name: chrome
    displayName: Google Chrome
    version: "149"
    image: selenium/standalone-chrome:<固定完整标签>
    platform: linux-amd64
    enabled: true
    default: true
    resources:
      cpus: 2
      memory: 3g
      shmSize: 2g
```

## 11. 网络与目标服务访问

### 11.1 Windows 本机服务

容器中的 `localhost` 指向容器自身。Windows 主机上的服务应使用：

```text
http://host.docker.internal:<端口>
```

例如：

```text
Windows 浏览器访问：http://localhost:3000
云浏览器访问：      http://host.docker.internal:3000
```

控制台提供“本机地址转换”功能：用户输入 `http://localhost:3000` 时，可以提示并转换为 `http://host.docker.internal:3000`。默认仅提示，不静默修改，以免改变用户真实测试目标。

本机开发服务必须监听可被 Docker 主机网关访问的地址。常见开发服务器需要设置 `0.0.0.0`，同时使用 Windows 防火墙限制访问范围。

### 11.2 同一 Compose 网络中的服务

若被测项目也通过 Docker Compose 运行，应加入共享测试网络，通过服务名访问：

```text
http://web:3000
http://api:8080
```

### 11.3 局域网服务

使用局域网 IP 或内部 DNS：

```text
http://192.168.1.50:8080
https://test.internal.example
```

### 11.4 线上服务

浏览器容器默认允许正常出站访问互联网。若公司网络要求代理，需要在浏览器能力和容器环境中配置 HTTP/HTTPS 代理与 `NO_PROXY`。

### 11.5 hosts 与 DNS

MVP 支持静态、管理员级别的 hosts 配置，通过 Compose `extra_hosts` 或内部 DNS 实现。V1 可支持会话级 hosts，但必须：

- 校验 IP 和域名格式；
- 限制最大条目数；
- 记录审计日志；
- 不允许修改宿主机 hosts；
- 会话结束后随容器一起销毁。

### 11.6 本地 HTTPS

优先方案是将本地开发 CA 根证书制作进派生浏览器镜像。临时验证可以通过浏览器参数忽略证书错误，但控制台必须醒目标记“已忽略证书错误”，防止把证书问题误判为测试通过。

### 12.1 登录与访问控制

- 首次启动通过环境变量或一次性初始化流程创建本地管理员。
- 支持本地用户名和密码登录。
- 密码使用 Argon2id 哈希，不存储明文。
- 使用 HttpOnly、SameSite Cookie 会话。

- 支持退出登录、修改密码和管理员重置本地用户密码。

### 12.2 浏览器目录

- 按浏览器品牌分组展示。
- 展示版本、通道、平台、是否默认、当前可用槽位和镜像是否已缓存。
- 支持按浏览器、版本、状态筛选。
- 不可用版本置灰并展示原因。
- 管理员可以启用、停用和设置默认版本。

### 12.3 创建会话

输入项：

- 浏览器；
- 浏览器版本；
- 启动网址；
- 分辨率；
- 语言；
- 时区；
- 会话时长；
- 是否录制；
- 是否接受不安全证书；
- 可选代理；
- 可选 hosts 映射；
- 会话名称和备注。

行为要求：

- 参数在服务端二次校验；
- 不允许用户提交任意 Docker 镜像名；
- 浏览器和版本只能从启用目录中选择；
- 达到并发上限时进入队列或明确拒绝；
- 启动失败返回可理解的错误，而不是原始 Java/Docker 堆栈；
- 会话创建成功后自动打开远程画面；
- 启动网址为空时打开 `about:blank`。

### 12.4 远程浏览器页面

- 嵌入 noVNC 画面；
- 支持鼠标、键盘、滚轮和中文输入验证；
- 支持全屏；
- 显示浏览器、版本、分辨率、已运行时间和剩余时间；
- 显示连接中、重连中、已断开、已过期状态；
- 支持截图；
- 支持手动结束；
- 支持管理员强制结束；
- 支持复制文本到浏览器会话；
- 剪贴板读取默认关闭，避免不必要地读取用户本机剪贴板内容；
- 浏览器开发者工具必须可正常打开和操作。

### 12.5 会话列表

- 展示本人或全部会话；
- 展示状态、浏览器、版本、创建人、开始时间、剩余时间和是否录像；
- 支持进入会话、结束会话和查看失败原因；
- 管理员可查看队列和资源占用；
- 刷新页面后可以恢复仍然有效的会话入口。

### 12.6 会话超时与清理

- 空闲超时和绝对超时分别配置；
- 到期前 5 分钟提示；
- 浏览器或 Viewer 断开不立即销毁，保留短暂重连窗口；
- 后端定期比对数据库、Grid Session 和 Docker 容器；
- 清理无数据库记录的孤儿浏览器容器；
- 将长时间卡在 `PROVISIONING` 的会话标记为失败并回收；
- 系统重启后执行一次恢复与清理扫描。

- 截图使用 WebDriver 截图能力或浏览器画面截图；
- 录像使用 docker-selenium 官方会话录像能力；
- 产物按 `用户/日期/会话ID` 存储；
- 文件名只包含安全字符；
- 下载必须鉴权并校验归属；
- 默认保留 7 天；
- 支持按日期和总容量清理；
- 删除会话元数据时可以选择是否保留产物。

### 12.8 管理设置

- 最大并发数；
- 默认和最大会话时长；
- 浏览器目录；
- 录像默认值；
- 产物保留天数和容量；
- 局域网访问开关；
- 允许访问的目标网段或域名，可选；
- Grid 状态、Docker 状态和磁盘空间；
- 版本信息和升级提示。

## 13. 会话状态机

```text
REQUESTED
    ↓
QUEUED
    ↓
PROVISIONING
    ↓
STARTING
    ↓
READY
    ↓
TERMINATING
    ↓
TERMINATED
```

异常状态：

- `FAILED`：创建或启动失败；
- `EXPIRED`：达到时长限制；
- `LOST`：数据库存在，但 Grid/容器已不存在；
- `ORPHANED`：容器存在，但数据库无对应有效会话，必须回收。

状态转换必须幂等。重复发送结束请求，应返回会话已经结束，而不是抛出 500。

## 17. Docker Compose 服务规划

Compose 顶层项目名使用 `jingcang`。优先在 `.env` 中设置 `COMPOSE_PROJECT_NAME=jingcang`，从而让自动生成的容器、网络和卷具有一致前缀；除非存在外部系统依赖，不手写固定 `container_name`，避免阻碍并行实例和 Compose 扩缩容。

```yaml
services:
  gateway:
    # Nginx：唯一对用户暴露的入口

  console-web:
    # 前端静态资源，生产模式可由 gateway 直接提供

  control-api:
    # API、Viewer Gateway、Worker

  selenium-docker:
    # Selenium Dynamic Grid 控制面

  docker-socket-proxy:
    # 可选：为 Dynamic Grid/后端提供受限 Docker API
```

网络：

- `jingcang_frontend`：gateway 与 control-api；
- `jingcang_backend`：control-api、Grid、浏览器子容器；
- `jingcang_test_targets`：可选共享网络，用于接入其他本地 Compose 项目。

卷：

- `jingcang_db`：SQLite；
- `jingcang_artifacts`：截图和录像；
- `jingcang_logs`：服务日志；
- `jingcang_selenium_assets`：Grid 录像和 session 元数据。

默认端口：

| 端口 | 暴露方式 | 用途 |
|---:|---|---|
| 80 或 8088 | `127.0.0.1` | 控制台统一入口 |
| 4444 | 默认仅内部；调试时绑定 `127.0.0.1` | Grid UI/WebDriver |
| 7900+ | 不直接暴露 | noVNC 由 Viewer Gateway 转发 |
| 5900+ | 不暴露 | 原始 VNC 禁止对外开放 |

## 19. 安全设计

### 19.1 默认网络边界

- 默认只绑定 `127.0.0.1`。
- Grid、SQLite、Docker API、noVNC 和 VNC 不直接暴露。
- 开启 LAN 模式时，只允许配置的私网 CIDR，并要求登录。
- 不提供默认公网部署配置。

### 19.2 Docker 安全

- 浏览器容器使用非 root 用户运行。
- 限制 CPU、内存、PID、共享内存和临时磁盘。
- 不挂载宿主机个人目录、项目源码或 Docker Socket到浏览器容器。
- 只有 Dynamic Grid 控制组件或受控 Orchestrator 能访问 Docker API。
- 优先使用 Docker Socket Proxy，并仅开放创建、查询、停止和删除受标签管理容器所需的最小接口。
- 所有系统创建的容器必须带命名空间标签，用于审计和安全清理。

### 19.3 Viewer 安全

- Viewer URL 必须包含短期签名令牌。
- Token 绑定用户、会话 ID、用途和过期时间。
- WebSocket 升级请求也校验令牌。
- 用户只能访问自己的会话，管理员除外。
- Viewer 不返回内部容器 IP、Docker ID 或 noVNC 密码。
- 会话结束后立即拒绝新的 Viewer 连接。

### 19.4 Web 安全

- 所有变更接口要求 CSRF 防护或同源 Token。
- API 使用 Zod/JSON Schema 做严格输入校验。
- 不接受前端传入任意 Docker 参数、镜像名、卷挂载或启动命令。
- 对 URL、代理、hosts、语言、时区和分辨率做白名单校验。
- 管理员操作写入审计日志。
- 对登录、创建会话、截图和延长会话做速率限制。
- 错误响应隐藏内部堆栈、文件路径和 Docker 细节。

### 19.5 访问目标的风险

云浏览器本质上可以访问本机和局域网，属于具有网络能力的执行环境。若控制台提供给多人使用，应增加：

- 允许/拒绝域名和网段策略；
- 阻止访问 Docker 内部管理地址和敏感元数据地址；
- 可选的只读代理审计；
- 明确的会话归属和操作日志。

- SQLite 数据库；

- 浏览器目录；
- 可选测试产物。

### 20.4 升级

1. 备份数据库与配置。
2. 拉取固定的新控制面镜像。
3. 预拉取新的浏览器镜像。
4. 在预发布目录验证启动、noVNC、本机服务和线上服务。

6. 执行数据库迁移。
7. 切换版本并运行健康检查。
8. 失败则回滚控制面镜像和数据库备份。

## 24. 验收标准

### 24.1 部署验收

- 在满足前置条件的新 Windows 电脑上，按文档可在 30 分钟内启动控制面；大镜像下载时间不计。
- 所有服务通过 Docker Compose 管理，不要求在 Windows 上单独安装 Java、MySQL、Nginx 或浏览器驱动。
- 控制台默认只能从本机访问。
- 重启电脑和 Docker Desktop 后，控制面可自动恢复。

### 24.2 功能验收

- 用户能看到 Chrome、Edge、Firefox 及其启用版本。
- 用户能创建浏览器会话并在网页中操作浏览器。
- 三种浏览器均可访问 `http://host.docker.internal:<端口>`。
- 三种浏览器均可访问指定线上 HTTPS 服务。
- 用户能打开浏览器开发者工具。
- 用户能手动结束会话。
- 会话超时后自动结束且不残留浏览器容器。
- 达到并发上限时系统排队或明确拒绝，不出现资源失控。
- 刷新控制台后仍能重新进入未结束会话。
- 用户不能访问其他用户的 Viewer 或产物。

### 24.3 稳定性验收

- 连续创建和销毁 50 个会话后无孤儿容器。
- 并发 4 个 1920×1080 会话运行 30 分钟，控制面不崩溃。
- 单个浏览器容器崩溃不会影响其他会话。
- API 重启后能识别现存 Grid 会话并恢复元数据或安全回收。
- noVNC WebSocket 连续运行 60 分钟无周期性断线。

### 24.4 安全验收

- 未登录用户不能创建、查看或结束会话。
- Viewer Token 过期、篡改或会话不匹配时被拒绝。
- API 不允许传入任意镜像、命令、卷或 Docker 参数。
- 浏览器容器内无法访问 Docker Socket。
- 日志中不出现密码、Cookie、Viewer Token 和 Authorization。
- 路径穿越不能读取 artifacts 目录之外的文件。
- Grid、VNC、noVNC 和 SQLite 不直接暴露到 LAN/公网。

## 25. 风险与缓解

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| Dynamic Grid 临时节点的 noVNC 路由不稳定 | 无法可靠嵌入画面 | 把 SPIKE-005 设为决策门；保留直接 Orchestrator 创建 standalone 容器的退出路径 |
| Docker Socket 权限过大 | 控制面被攻破时影响宿主 Docker | Socket Proxy、最小 API、网络隔离、控制面非 root、浏览器不挂载 Socket |
| 浏览器镜像体积大 | 首次启动慢、磁盘增长 | 预拉取、固定矩阵、清理旧镜像、显示缓存状态 |
| 浏览器老版本不可获取或不可运行 | 无法覆盖全部历史版本 | 维护有限版本矩阵；特殊版本转移到遗留 VM |
| Linux 浏览器与 Windows 表现不同 | Windows 字体、编码、媒体差异 | 对关键项目增加 Windows 节点；在报告中标记平台 |
| WebKit 不等于 Safari | Safari 兼容结论不完整 | 最终发布前使用 macOS Safari 验证 |
| 本机服务只监听 127.0.0.1 | 容器无法访问 | 提供框架配置示例和连通性诊断 |
| 自签名证书不受信任 | HTTPS 测试失败 | 派生镜像安装本地 CA；临时模式醒目标记 |
| noVNC 输入法和剪贴板差异 | 中文操作体验下降 | 先做输入验证；提供文本注入辅助；不默认读取本机剪贴板 |
| 录像快速占满磁盘 | 服务不可用 | 默认关闭、容量上限、保留策略、磁盘健康检查 |
| Docker Desktop 更新造成兼容变化 | 系统突然不可用 | 固定并记录已验证版本，升级前做备份和预发布验证 |

4. 启动 gateway、control-api 和 Grid。
5. 执行 `/health/ready`。
6. 运行 `verify.ps1`，分别创建 Chrome、Edge、Firefox 会话。
7. 验证本机测试页和线上测试页。
8. 验证结束会话后无残留容器。
9. 保存当前镜像 digest 和配置备份。

### 26.2 回滚

- 控制面镜像保留前一个稳定 digest；
- 数据库迁移前自动备份；
- 回滚时停止接收新会话；
- 结束或等待现有会话；
- 恢复上一版本 Compose、镜像和数据库；
- 运行健康检查和三浏览器冒烟测试。

浏览器目录升级可以独立回滚，不要求回滚整个控制面。

## 27. 后续扩展路线

### 27.1 Playwright

增加 Playwright 项目模板，在 Chromium、Firefox、WebKit、Chrome、Edge 上执行自动化回归，并把 HTML 报告挂载到控制台。人工浏览器云与 Playwright 共用目标地址、CA、代理和浏览器矩阵策略，但不强制共用同一种容器生命周期。

### 27.2 Windows 与 IE

若业务明确要求 Windows 专属兼容性：

- 增加 Windows VM；
- 安装 Selenium Node 和对应浏览器；
- 注册进同一 Grid 或独立遗留 Grid；
- 远程画面通过 RDP/Guacamole；
- 控制台统一展示，但标记平台与安全等级；
- 老 Windows/IE 节点使用隔离网络和合法许可证。

### 27.3 Safari

增加一台受支持的 Mac 设备，运行 Safari/WebDriver 节点，或者把测试任务转发至合规的外部真机云。真实 Safari 不纳入 Windows Docker 单机范围。

## 28. 实施建议

建议严格按以下顺序推进：

1. 完成 Epic 0，不提前建设大量 UI。
2. 冻结 Dynamic Grid Viewer 路由或降级架构。
3. 用最小后端创建和终止会话。
4. 打通 Viewer Gateway。
5. 再建设浏览器卡片和完整前端。
6. 完成超时、恢复和孤儿清理后，才增加录像等高资源能力。
7. 最后完善局域网访问、动态 hosts 和扩展节点。

第一阶段成功标准不是“界面完整”，而是稳定打通：

```text
选择浏览器
  → 创建隔离 Session
  → 网页中看到并操作浏览器
  → 访问本机服务和线上服务
  → 结束 Session
  → 容器和临时数据被完整回收
```

只要该闭环通过，F2etest 风格的展示和管理能力就属于可控的产品开发工作。

## 30. 待决策项

在 Epic 0 完成后，必须确认以下事项：

1. Dynamic Grid 的 noVNC Viewer 映射是否采用官方节点信息、Docker 标签，还是直接容器编排降级方案。
2. 第一版是否只允许单个本地管理员，还是同时支持多个 tester 用户。
3. 默认控制台端口使用 80 还是避免管理员权限和端口冲突的 8088。
4. 是否在 MVP 启用录像；建议默认不启用。
5. 浏览器首批固定版本矩阵。
6. 本地 HTTPS 使用统一开发 CA，还是先允许临时忽略证书错误。
7. 是否需要局域网其他设备访问；建议 MVP 只允许本机。
8. 是否需要把被测项目自动加入共享 Docker 网络。

未明确选择时，本文档采用以下默认值：单管理员、本机访问、端口 8088、最大并发 4、会话 60 分钟、录像关闭、Chrome/Edge/Firefox 各一个稳定版本、通过 `host.docker.internal` 访问本机项目。
