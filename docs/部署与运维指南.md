# 镜舱（JingCang）部署与运维指南

> 对应开发任务计划 CORE-008。本文覆盖 Windows / Linux / macOS 三种宿主的部署、生产环境变量与密钥、备份/迁移/升级、离线部署，以及安全与 CI 门禁。
> 平台基线：`JingCang v1.3.0`（本地 `D:\codex\jingcang`）。多端云测试能力（Android 云手机 / 移动浏览器 / iOS 真机）见 `docs/JingCang-多端云测试平台-开发任务计划.md`。

---

## 1. 部署形态概览

| 形态 | 编排文件 | 适用场景 |
|---|---|---|
| 开发 / 单机评估 | `deploy/compose.yaml` | Windows（Docker Desktop + WSL2）、Linux、macOS 本地快速体验 |
| 移动设备云开发 | `deploy/compose.mobile-dev.yaml` | 接入 Device Agent、验证节点注册 / 心跳 / 设备目录 |
| PoC | `deploy/compose.poc.yaml` | 真机 / 模拟器联调 |
| 生产 | `deploy/compose.production.yaml` | Linux 服务器长期运行，含 Nginx 网关、只读文件系统、健康检查 |
| 离线 | `scripts/install-offline-production.ps1` + 镜像包 | 无外网环境，镜像预打包分发 |

所有形态共享同一套镜像：`jingcang/control-api`（控制面）、`nginx`（网关）、`selenium/standalone-*` 浏览器舱、以及可选 `jingcang/browser-bundle`（离线浏览器镜像）。

---

## 2. 前置要求

- **Docker Engine 24+**；Windows 需 **Docker Desktop + WSL2** 且分配 ≥ 8 GB 内存（并发多时 16–32 GB）。
- 仅**本地源码开发**需要 Node.js ≥ 22 与 pnpm ≥ 9（推荐 `pnpm@11.1.2`）。生产部署只需 Docker。
- 离线部署需准备离线镜像包、`SHA256SUMS.txt`、`PLATFORM.txt` 与填写好的 `.env.production`。

---

## 3. 环境变量与密钥

控制面在启动时校验以下**强制密钥**，占位符或长度不足会被拒绝启动：

| 变量 | 最小长度 | 说明 |
|---|---|---|
| `JINGCANG_SESSION_SECRET` | 32 | HttpOnly Cookie 会话签名密钥 |
| `JINGCANG_VIEWER_SECRET` | 32 | 短期 Viewer Token（WebSocket 鉴权）HMAC 密钥 |
| `JINGCANG_ADMIN_INITIAL_PASSWORD` | 12 | 初始管理员密码（首次登录后请立即修改） |

生成强密钥（任选其一）：

```powershell
# Windows
.\scripts\bootstrap.ps1        # 自动生成随机密钥并写入 .env
```

```bash
# Linux / macOS
openssl rand -hex 32   # 用于 SESSION_SECRET / VIEWER_SECRET
openssl rand -hex 16   # 前缀 + 自定义串作为管理员密码，长度 ≥ 12
```

常用运行变量（均有默认值，按需覆盖）：

| 变量 | 默认 | 说明 |
|---|---|---|
| `JINGCANG_PORT` | 8088 | 对外端口 |
| `JINGCANG_BIND_HOST` | 127.0.0.1 | 绑定地址；生产容器内固定 `0.0.0.0`，由 Nginx 收敛 |
| `JINGCANG_LAN_ACCESS_ENABLED` | false | 是否允许非回环绑定 |
| `JINGCANG_GRID_URL` | http://selenium-docker:4444 | Selenium Grid 地址 |
| `JINGCANG_SQLITE_JOURNAL_MODE` | WAL（容器 DELETE） | Windows 挂载卷建议 `DELETE` 以避免 `SQLITE_IOERR` |
| `JINGCANG_TRUST_PROXY` | false | 前置反代时设为 `true` |
| `JINGCANG_SESSION_MAX_CONCURRENCY` | 4 | 并发舱位上限 |
| `JINGCANG_BROWSER_OFFLINE_MODE` | false | 离线浏览器镜像模式 |
| `JINGCANG_MOBILE_AGENT_URL` | — | 移动设备云开发形态下指向宿主 Agent（如 `http://host.docker.internal:19879`） |

**安全红线**：`.env` / `.env.production` 含真实密钥，**禁止提交到仓库**；示例见 `.env.example`、`deploy/.env.production.example`。

## 4. Windows 部署（Docker Desktop + WSL2）

```powershell
# 1. 生成安全配置（一次性输出管理员密码并写入 .env）
.\scripts\bootstrap.ps1

# 2. 启动整套平台
docker compose -f deploy/compose.yaml up -d --build

# 3. 健康检查
docker compose -f deploy/compose.yaml ps
# 浏览器访问 http://localhost:8088
```

常用运维：

| 场景 | 命令 |
|---|---|
| 查看日志 | `docker compose -f deploy/compose.yaml logs -f control-api` |
| 平滑重启 | `docker compose -f deploy/compose.yaml restart` |
| 停止清理 | `docker compose -f deploy/compose.yaml down` |

## 5. Linux 部署（生产推荐）

```bash
# 1. 准备生产环境文件（填写强密钥，禁止 change-me 占位）
cp deploy/.env.production.example deploy/.env.production
# 编辑 deploy/.env.production：设置 JINGCANG_SESSION_SECRET / VIEWER_SECRET / JINGCANG_ADMIN_INITIAL_PASSWORD

# 2. 启动（含 Nginx 网关、只读容器、健康检查）
docker compose -f deploy/compose.production.yaml up -d --build

# 3. 健康检查
curl -fsS http://localhost:8088/health/ready   # 期望 HTTP 200
```

- 生产 `compose` 已用 Nginx 网关收敛 8088、容器 `read_only` + `tmpfs`、`no-new-privileges`，并挂载 Docker Socket 以动态拉起浏览器舱——请在受信内网或配合外部 TLS 反代使用。
- 对外暴露仅限 8088；不要将 4444（Grid）、5900（VNC）暴露在公网。

## 6. macOS 部署（iOS 节点 / 本地开发）

- 控制面与控制台与 Linux 完全一致（Docker Desktop 启动 `compose.yaml`）。
- **iOS 真机节点不跑在 Docker 内**：macOS 宿主（Monterey+）需安装 Xcode / Command Line Tools，并连接经开发者模式信任的真实 iPhone，由 iOS Device Agent 向控制面注册。详见计划文档 `IOS-001~008`。
- 本地开发可直接用 `pnpm` 运行（见 README 的「本地工程开发」）。

## 7. 移动设备云接入（Android / iOS）

1. 启动 Device Agent（Windows / Linux 宿主）：

   ```bash
   JINGCANG_NODE_ID=win-agent-01 \
   CONTROL_API_URL=http://localhost:8088 \
   AGENT_TOKEN=<管理员下发的节点令牌> \
   node apps/device-agent/dist/index.js
   ```

2. 控制面管理员在控制台或通过 API 注册节点，获得一次性 **64-hex 凭据**（库内存 SHA-256，明文仅返回一次）。
3. Agent 周期性心跳（携带 Bearer 凭据）并上报设备清单；控制面 `GET /api/v1/devices`、`GET /api/v1/device-profiles`、`GET /api/v1/device-nodes` 聚合为可调度目录。
4. 撤销节点：凭据立即失效，后续心跳返回 `401`。

> 真机 / 模拟器 / ADB / iOS 的实操依赖硬件 PoC（计划文档 AND-002~006、IOS-001~005），本指南只描述控制面接入面。

## 8. 备份 / 迁移 / 升级

- **数据位置**：生产为 `jingcang_prod_db` 卷；单机为 `data/db/jingcang.sqlite`。
- **备份**：
  - 控制面内置 `backupDatabase()` 可物理备份（含 `-wal`/`-shm`）。
  - 生产卷可用 `docker volume inspect jingcang_prod_db` 定位后复制，或停服后 `docker run --rm -v jingcang_prod_db:/data -v $PWD:/backup busybox cp -a /data /backup`。
- **迁移（版本化，幂等）**：数据库schema以编号迁移演进（`apps/control-api/src/db/migrations.ts`），启动自动执行，历史 `mobile_sessions` 旧表会**自动补列 + backfill**，旧会话数据不丢失；异常迁移可回滚（`rollbackTo`）。
- **升级流程**：① 备份数据 → ② 拉取新镜像（`up -d --build`）→ ③ 健康检查 `/health/ready` → ④ 观察日志确认迁移完成。迁移为幂等，可重复执行。

## 9. 离线部署

物料（由离线打包流程生成，不在源码仓库内）：

- 生产镜像 tar 包 `images/production-images.tar`
- `SHA256SUMS.txt`（每个物料的 SHA-256）
- `PLATFORM.txt`（目标 Docker 平台，如 `linux/amd64`）
- 填写好的 `.env.production`

执行：

```powershell
# 校验 checksum + 平台 + 三项强密钥 → docker load → 启动（--pull never）
.\scripts\install-offline-production.ps1 -Start
```

- 脚本会拒绝占位符密钥（`change-me-`）与长度不足的变量。
- **镜像包须与目标宿主平台一致**（如 `linux/amd64`），否则 `PLATFORM.txt` 校验失败。

## 10. 安全与合规

- 控制面零挂载宿主机 Docker Socket 的**替代方案**：生产 `compose` 为支持动态浏览器舱而挂载 `docker.sock`，请仅在受信内网使用，并配合 Nginx/TLS 反代收敛入口。
- Viewer Token 绑定 `user / session / device / lease` 四元组（HMAC-SHA256）；节点凭据仅存 SHA-256 摘要，明文一次性返回。
- 密码 `scrypt` 加盐哈希；登录限流；产物路径穿越校验。
- 审计事件写入 `audit_events`，覆盖登录、建会、终止、审批、权限变更等。
- 仅暴露 8088；4444 / 5900 不得公网可达。

## 11. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| `SQLITE_IOERR`（Windows 挂载卷） | 设 `JINGCANG_SQLITE_JOURNAL_MODE=DELETE` |
| 升级后旧会话表缺列报错 | 迁移已自动补列；若来自极早期库，请先备份再启动，观察迁移日志 |
| 控制面拒绝启动，提示密钥不安全 | 使用了 `change-me-*` 或默认弱密钥；用 `bootstrap.ps1` / `openssl rand` 生成强密钥 |
| 设备目录看不到节点 | 检查 Agent 心跳是否携带合法 64-hex Bearer 凭据；节点注册后凭据才有效 |

## 12. CI 与质量门禁

- **CI 流水线**：`.github/workflows/ci.yml` —— `verify`（lint → build → 契约测试 → 单元/集成测试）、`security`（依赖审计 `pnpm audit` + 密钥扫描 `gitleaks`）、`package`（生产镜像 build-only）。
- **发布容器**：`.github/workflows/publish-containers.yml` —— 手动 `workflow_dispatch` 按版本号构建并推送 `ghcr.io` 镜像与浏览器离线包。
- 本地等价验证：`pnpm -r lint && pnpm -r build && pnpm -r test`。
